# Review correction to the historical preregistrations

This is a correction record for [PREREGISTRATION.md](PREREGISTRATION.md) and
[PREREGISTRATION-RECOGNITION.md](PREREGISTRATION-RECOGNITION.md). Neither
historical file is modified. It reports what the checked-in models actually
show; it does not retroactively preregister revised predictions or claim a
new textual finding.

1. **TK-C1/P-TK1:** the first preregistration contains inconsistent counts:
   its list of seven includes Śiva, while another sentence says “seven named
   + Śiva.” The Boolean model obtains seven surviving rows, but has no proven
   one-to-one textual-class mapping and does not encode the positional
   distinction among mantra classes. P-TK1 remains unestablished. P-TK1b is a
   proposed interpretation, not structurally confirmed by the model. The
   measured clause/row ratio is an arithmetic statistic for this encoding,
   not demonstrated compression of a traditional classification.
2. **TK-C2:** the preregistered rule and expected Pralayākala-row change differ
   from the implemented R1 deletion and 7-versus-8 count. The implemented
   mutation is a valid negative control for the checked Boolean proposition;
   it does not constitute a successful execution of the original TK-C2 plan.
3. **R-REC3:** an owner-authored A–F chain is reconstruction (R), not root
   text (T). The Boolean assignments show independence only under the model's
   lack of constraining premises. Source pins and bridge premises are pending.
4. **R-REC2/4/6/8:** selected flag witnesses are not transitions or a proof
   of physical/psychological independence; the Boolean equalities are not a
   general sheaf theorem; one PI/ground example is not full independence.
5. **Memory:** the implemented premise is M4 → (M1 ∧ M2 ∧ M3), not the
   converse. A separate theorem demonstrates the converse does not follow.
6. The base Git history first publishes the preregistration and Lean source
   together. It does not independently verify their earlier authoring order.
   Future experimental preregistrations should be committed and published
   before code or results, then referenced by an immutable commit in the run.

edition and rights caveats, checks, and the proposed integration contract.
